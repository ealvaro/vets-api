## Classification rules:
- A service is an **upstream dependency** ONLY if the class itself makes outbound HTTP calls
  (e.g., via Faraday, RestClient, Net::HTTP, or inherits from Common::Client::Base).
- Redis clients, cache wrappers, adapters, serializers, and other utility classes
  that do NOT make HTTP calls are **internal** — add them to excluded_classes.
- Do NOT classify a class as upstream based on what other classes in its namespace do.
  Classify only the specific class presented.

## Upstream group overrides:
Some services route through a different upstream than their namespace suggests.
Use these mappings instead of inferring from the class name or namespace:
- `Ccra::` classes → map to **"VAOS"** (CCRA data is received through the VAOS service)

## Examples:
- `SomeModule::ApiClient` (inherits Common::Client::Base, calls Faraday) → upstream
- `SomeModule::RedisClient` (reads/writes Rails.cache) → excluded (internal)
- `SomeModule::Adapter` (transforms data structures) → excluded (internal)
